# Общие правила

Действуют во всех проектах. Проектный `CLAUDE.md` и `.claude/workflow.md` уточняют и приоритетнее.

## 0. Стоп-правила <!-- subagent -->

Остановись и спроси, не угадывай, если собираешься:

1. **назвать параметр или метод внешнего API или сослаться на стандарт** (RFC, HTTP-коды, OAuth, закон), не открыв первоисточник (официальная документация, текст стандарта с разделом; WebFetch может отдать старый кеш — при сомнении `curl` и греп); вывод, которого в цитате нет дословно, — толкование, решает пользователь;
2. **сослаться на колонку или таблицу БД**, не проверив миграции или схему;
3. **написать что-либо наружу** — тред PR, трекер, письмо, чат команды; `[хук]` для GitHub (`gh` на запись: PR, ревью, ответы, issues, `gh api`) и YouTrack (MCP-инструменты записи); запись в API GitHub через `curl` или скрипт с токеном запрещена — только `gh`; создание PR — шагом отправки (§2);
4. **расширить scope** за пределы постановки;
5. **объяснить наблюдаемое поведение чтением исходников** вместо проверки подменой значения;
6. **заменить документированный случай ответа внешнего API наблюдённым в пробе** — проба добавляет свою форму к документированной; опровергает доку только дословная цитата первоисточника;
7. **направить команду с БД не в тестовую базу** — креды дев/прод из docker или env без подтверждения пользователя не подставлять: риск снести данные.

Посчитанное, исследованное, сведённое в документ — проверь до выдачи. Правдоподобно ≠ проверено.

## 1. Общение

- Отвечай по-русски, кратко, простым языком. `[слово]`
- Не делай того, о чём не просили: не обновляй память, не рефактори соседнее, не уходи в смежную тему. `[слово]`
- В auto-режиме правки делай без вопросов; спрашивай только про необратимое и внешнее. `[слово]`
- Тексты для команды и ответы в треды — голосом пользователя: слитно, по сути, без благодарностей и извинений. `[слово]`
- В текстах для команды и вопросах на уточнение — ни одного имени таблицы, колонки, статуса или класса; суть словами бизнеса, к вопросу — пример с цифрами. Код и схема БД — только если спросили. `[слово]`
- На решение пользователя отвечай не «ок», а одним из трёх: аргумент за с проверкой по коду, аргумент против с тем же, «не могу оценить без X». Согласие без основания — нарушение, `retro` считает. `[слово]`
- Посылку решения опровергла проверка — «не меняю, фиксирую» запрещено. Есть источник, образец в проекте или умолчание (fact-checker, колонка «кто решает») — исправь сам и запиши; настоящий выбор — пользователю с рекомендацией, его ответ цитатой в `design.md`. Без записи implementer не зовётся. `[хук]`
- К любому добавлению — своему, пользователя, ревьюера — вопрос «какое требование нарушим, если не делать?»; ответ «никакое» фиксируется в `design.md`/`spec.md` как осознанное расширение с датой или отбрасывается. `[слово]`
- Отчёт для команды (коммент в тикет, итог ресёрча, оценка) — по скелету `task-workflow/references/team-report.md`: первая строка — что это и для кого, разделы-этапы с итогом в заголовке, блоки по смыслу с номерами задач хвостом, один экран, числа из одного источника. `[слово]`

## 2. Git <!-- subagent -->

- Пушь только по команде пользователя. PR создавай только шагом отправки (`branch-ops` D) через `gh pr create --title … --body-file …`, показав заголовок и описание и получив «да»; `gh pr create --fill`/`--web`/`--editor` запрещены. `[хук]`
- Расхождение с базовой чини rebase + `--force-with-lease`, не merge (`git merge`, `git pull` без `--rebase`). `[хук]`
- Ветка на ревью: правки — новыми коммитами, без amend и force; название по сути правки, согласуй до коммита; разные правки — разные коммиты. `[слово]`
- Без трейлеров и подписей в коммитах. `[настройка attribution]`
- `git add` — явными путями (в ветке тикета `-A`/`.`/каталог идут через подтверждение); локальные правки пользователя (секция «Не коммитить» в `workflow.md`) не коммить. `[хук]`
- Не заводи worktree, если пользователь уже в нужной ветке. `[слово]`

## 3. Проверки и отчёт <!-- subagent -->

- В отчёте называй, какие проверки прогнаны и на каком sha; слово «чисто» без перечня запрещено. `[слово]`
- Проверки перед пушем — последним шагом на финальном дереве (`$DEVFLOW_ROOT/hooks/pre-push-check.py`); любая правка обнуляет. `[хук]`
- Долгие команды дожидайся до итоговой строки; фоновый процесс умирает вместе с ходом. `[слово]`
- Полный прогон тестов — один раз, последовательно, не в нескольких агентах (lock на прогон). `[хук]`
- Пуш ветки тикета требует карт модулей по всем файлам ветки (`paths`), строки `сверено` (коммит, после которого файлы модуля не менялись) и `<KEY>/map.md`; без `architecture_dir` гейт молчит. `[хук]`
- Обязательные агенты по режимам — `task-workflow/references/cycles.md`; Stop-хук блокирует ход без них один раз с текстом, кого вызвать. `[хук]`
- Отчёт о завершении: что сделано / как проверено / **что осталось непроверенным** (отдельным блоком, даже если «ручная проверка не проводилась») / что вне зоны. `[слово]`
- Однотипную проблему чини по всему диффу сразу, не только в указанном месте. Мёртвый код удаляй по всей цепочке (вызывающие, DI, маршруты, тесты); рефакторинг конвертирует все копии паттерна, не одну. `[ревьюер]`
- После ребейза, своего или чужого, — сначала проверки и тесты затронутых модулей и дифф с базой по файлам вне задачи (чужие правки не откатились, сырой SQL не ссылается на переименованное в базе), потом правки: конфликты разрешены без прогона, и сломанное до тебя смешается с твоим диффом. `[слово]`
- Прогон, которого не было, в отчёте не упоминай; «проверки прошли» без команды и sha — не отчёт. `[слово]`
- Риск, найденный своим ревью и ведущий на проде к 500, расхождению денег и статусов или показу данных чужого владельца, не уходит в «вне объёма» или «открытые вопросы» PR: чини или выключай флагом до правки другой стороны; «было до задачи» не освобождает, если задача открыла к риску новый путь. `[ревьюер]`

## 4. Тикеты

- Работа с тикетами — скилл `task-workflow`; трекер YouTrack — `tracker`; ветки и PR — `branch-ops`.
- Зачёркнутое (`~~…~~`) в тикете и комментариях — закрыто, в работу не брать. `[слово]`
- Явно написанное в постановке не выносить на уточнение — перечитай тикет до вопроса. `[слово]`
- Вложения тикета скачивай сам (`youtrack.mjs attachments`, скилл `tracker`). `[слово]`
- Оценка задачи — текстом с декомпозицией по пунктам, не таблицей; подгонка под норматив — явный список урезанного. `[слово]`
- В плане задачи отдельным пунктом — сколько запросов делает решение и где риск N+1. `[слово]`
- Карта области (`<KEY>/map.md`, `system-mapper`) — до плана; сценарии приёмки фиксируются до кода, изменение по ходу — решение пользователя в «Изменения сценариев» `spec.md` с датой. `[слово]`
- Сужение критерия приёмки согласуй с постановщиком до реализации; отклонение, записанное в описании PR, — не согласование. `[слово]`

## 5. Код <!-- subagent -->

Общее для всех проектов; имена классов, слоёв и инструментов — в проектном `CLAUDE.md`.

- Сравнения строгие (`===`/`!==`), не `==`. `[ревьюер]`
- Оркестрация — в сервисном слое: генерация значений, retry, побочные эффекты, многошаговые сценарии. Контроллер принимает запрос, зовёт сценарный слой, отдаёт ответ; модель/сущность — тонкий слой данных. `[ревьюер]`
- DTO — в своём слое, не рядом с кодом, который их использует. `[ревьюер]`
- Новый компонент — по паттерну и образцу того же типа из проекта, в его слое (deptrac или аналог); переходный каталог — только без образца в слоях; развилка поведения в общем сценарии — паттерном (Strategy/хук), не замыканием или перестановкой шагов. Паттерн, путь образца и слой фиксируются до кода: блок «Паттерны и образцы в проекте» `design.md` проверяет `spec-critic` design до плана (без вызова Stop-хук не отпускает ход, без отчёта нет `plan.md` и implementer) `[хук]`; строку «Образец» пункта `tasks.md` в small/bounded и размещение в диффе сверяет ревьюер `[ревьюер]`.
- Повторяющееся поведение — в абстрактный базовый класс, не копия трейта/хелпера в каждый класс; объединяя дубли, сверь поведение потомков (лимиты, ранние выходы). `[ревьюер]`
- Связи, которые читаются в цикле, — через предзагрузку; методы из цикла принимают список и вызываются один раз. `[ревьюер]`
- Тяжёлые запросы: объём данных и индексы оцениваются до того, как запрос попадёт в код. `[ревьюер]`
- Обоснования решений в комментариях и прозу в докблоках не пиши: обоснование идёт в отчёт задачи; пояснение неочевидного терма запроса одной строкой допустимо, при переносе кода существующие пояснения сохраняй. `[ревьюер]`
- Миграции создавай только командой проекта (`migration_create` в `workflow.md`), не файлом руками. `[хук]`
- Гонка на деньгах и состоянии: атомарный UPDATE с условием вместо проверки-перед-записью; сумма считается по живому значению в SQL, не по снимку; идемпотентность денежной операции — UNIQUE в БД; гонка на создании — 409, не 500. `[ревьюер]`
- Ассерт проверяет значение, не факт существования; тест, который не может упасть, — не тест; правка существующей ручки тянет её тесты. `[ревьюер]`
- Новый провайдер, очередь или способ применения настройки — тем же PR обнови всё, что описывает прежние варианты: README модуля, комментарий в `.env.example`, проектную карту. `[ревьюер]`
