# Стандарт скилла devflow

Единая структура `SKILL.md` для всех скиллов плагина. Линт — `tools/skill-lint.py` (вызывается из `tools/check.sh`, тесты `hooks/tests/test_skill_standard.py`).

## 1. Принципы

**Из Рамазанова (правила и скиллы).**
- Правило — по потребности: ошибка → правило, повтор работы → скилл. Не писать стандарт «на будущее».
- Маленькие тематические файлы: `SKILL.md` — маршрутизатор до 6 КБ, подробности этапов — `references/<этап>.md`, по файлу на тему.
- Пример вместо описания: каждый формат вывода сопровождается коротким примером, не прозой о том, какой он должен быть.
- Добавил — прогнал кейс: правка скилла проверяется на сценарии, который её породил, и соседних; без прогона — гипотеза.
- Актуальность вместе с кодом: сменился шаг процесса, агент, поле конфига — тем же коммитом правится скилл.
- **Скилл против плейбука.** Скилл — единичное действие с одним выходом (`tracker`): запрос → команда → отчёт. Плейбук — многошаговый режим с этапами и единым форматом отчёта «реализовано / риски / блокер / следующий шаг» (`task-workflow`, `branch-ops`). Оба оформляются одним шаблоном; у плейбука раздел «2. Режимы» ведёт в `references/`, у скилла «2. Этапы» укладывается в `SKILL.md`.

**Из Розума (карта и навигация).**
- «Границы» — что скилл не делает и к чему не применяется автоматически → разделы «Когда / когда нет» и «1. Протокол».
- «Как собрать данные» — нумерованные шаги с проверкой источника на каждом → «2. Этапы» / `references/<режим>.md`.
- «Формат результата» с примером → «4. Отчёт».
- «Размещение и готовность» — чек-лист перед выдачей → «Самопроверка».

**Из Gopnik (состязательность и честность).**
- «Зачем существует» — один абзац с кейсом провала, который скилл ловит; без кейса скилл не нужен.
- «Когда запускать / когда не нужно» — триггеры и анти-триггеры словами пользователя.
- «Условие остановки» — признак, что скилл стал шумом или работает для галочки (ноль находок десять запусков подряд, пользователь перестал читать отчёт).
- «Самопроверка перед выдачей» — чек-лист; каждая строка помечена: **проверяется машинно** (хук, линт, тест) или **держится на честности** (слово). Честность — не гарантия, поэтому таких пунктов должно становиться меньше.

## 2. Шаблон `SKILL.md`

```
---
name: <имя каталога>
description: <по-русски: триггеры в кавычках («…», «…») + «Не для …»>
---
# <Имя> — <одна строка>

## Зачем
Кейс провала, который скилл ловит: один абзац с реальным случаем.

## Когда / когда нет
Триггеры словами пользователя; чего скилл не делает и куда идти вместо него.

## 0. Конфиг проекта
Поля `.claude/workflow.md` (и `.env`), которые читает скилл; «не читает» — тоже ответ.

## 1. Протокол
Сквозные правила для всех этапов, с метками `[хук]` / `[слово]` / `[ревьюер]`.

## 2. Этапы  |  ## 2. Режимы
Таблица: запрос → этап/режим → `references/<режим>.md`; у каждого — вход, выход, проверка.

## 3. Цикл
Обязательные агенты (ссылка на `task-workflow/references/cycles.md`) или «агентов нет».

## 4. Отчёт
Формат итоговой строки или блока с примером.

## Остановка
Признак шума или формальности, при котором скилл пересматривается.

## Самопроверка
Чек-лист перед выдачей; у пункта пометка: машинно (чем) / на честности.
```

Размер `SKILL.md` — не больше 6144 байт; всё, что длиннее, уезжает в `references/`. Заголовки разделов — дословно по шаблону (линт ищет по началу строки); `## Overview` запрещён.

## 3. Линт (`tools/skill-lint.py`)

По каждому `skills/<имя>/SKILL.md`:
1. фронтматтер с `name` и `description`; `description` по-русски и содержит «не для»;
2. обязательные разделы: `## Зачем`, `## Когда`, `## 0. Конфиг`, `## 1. Протокол`, `## 2. ` (Этапы или Режимы), `## 3. Цикл`, `## 4. Отчёт`, `## Остановка`, `## Самопроверка`;
3. размер ≤ 6144 байт;
4. каждый упомянутый `` `references/<имя>.md` `` существует;
5. нет `## Overview`.

Текст нарушения называет действие: `skill-lint: <скилл>: нет раздела ## Остановка — добавь (признак шума или формальности)`.

## 4. Новый или изменённый скилл

Поведение и раскладка меняются одним коммитом со всем, что их описывает (README, `cycles.md`, справочники). Проверка — `python3 tools/skill-lint.py skills/<имя>` и прочтение скилла на сценарии, с которого он обычно запускается.
