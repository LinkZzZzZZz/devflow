# devflow

Плагин Claude Code с процессом ведения задач: от постановки в YouTrack до ветки с PR на GitHub и правок по ревью.
Проектно-независимое лежит здесь; всё проектное — в одном файле `.claude/workflow.md` репозитория (ключ тикета и проект
YouTrack, сторона репозитория, базовая ветка, команды проверок, миграции, локальный стек, карта правил для ревью,
стековые хуки). Правила кода — в `CLAUDE.md` проекта с метками `[хук]`/`[ревьюер]`/`[слово]`.

Процесс: `task-workflow` ведёт тикет (spec → карта области → план → реализация → маршрут ревью) → агенты `spec-critic`, `system-mapper`, `decision-critic`, `implementer`, `quality-reviewer`,
`security-reviewer`, `db-reviewer`, `black-box-tester`, `fact-checker` → гейты хуков (проверки перед пушем, база знаний, локальные файлы, миграции, PHP-правила, циклы агентов по режимам)
→ `/devflow:ship` отправляет ветку и создаёт PR → `resolve-pr-comments` разбирает замечания ревью → шаг «Уроки» и `/devflow:learn-pr` превращают их в правила (журнал находок `~/.claude/devflow/review-findings.jsonl`).

## Состав

| Тип | Имя | Назначение |
|---|---|---|
| скилл | `task-workflow` | тикет от постановки до готовой ветки; режимы new-ticket, start, implement, finish, fixes, show, estimate, status, epics |
| скилл | `branch-ops` | ребейз, отправка ветки с созданием PR (`gh pr create`), синхронизация своих PR с базой |
| скилл | `review-pr` | ревью чужого PR: находки списком, на GitHub — одно ревью с выбранными комментариями |
| скилл | `resolve-pr-comments` | правки по замечаниям ревью в своём PR, ревьюер по коммиту правок, ответы в треды после «ок» |
| скилл | `tracker` | YouTrack только на чтение: карточка, комментарии, вложения, «что в работе», «что зависло» по стороне |
| скилл | `retro` | уроки сессии, сверка меток правил с механикой, метрики поддакивания (команда `/devflow:retro` — обёртка) |
| агент | `implementer` | реализует одну подзадачу плана по брифу |
| агент | `quality-reviewer` | ревью диффа по общему чек-листу и правилам `[ревьюер]` из `CLAUDE.md` |
| агент | `black-box-tester` | покрытие сценариев спеки и исполнение ручного сценария на локальном стеке |
| агент | `fact-checker` | проверка фактов о внешнем мире в spec/design до реализации: API, схема, нормы стандартов с цитатой |
| агент | `spec-critic` | критика постановки до кода; в режиме design — обязательные блоки `design.md`, контракт API, паттерн и образец проекта |
| агент | `security-reviewer` | дифф одной линзой: владение, mass assignment, лишнее в ответе, секреты, идемпотентность платежей |
| агент | `db-reviewer` | новые запросы на реальной схеме: EXPLAIN, индексы, объём, N+1 (только чтение) |
| агент | `system-mapper` | карты модулей, карта области до задачи, маршрут ревью по сценариям и таблица «проблема → трасса → код» после; код не меняет |
| агент | `decision-critic` | критик решений и диагнозов в чистом контексте с мандатом «опровергни»: CONTINUE / REVISE / BLOCK |
| команда | `/devflow:ship` | сквош, коммит от текущего времени, проверки, пуш, PR, проверки CI |
| команда | `/devflow:sync-prs` | конфликты и отставание своих PR |
| команда | `/devflow:map` | карта модуля вне тикета: `/map <модуль|путь> [area|feature|troubleshooting]` |
| команда | `/devflow:retro` | обёртка над скиллом `retro` |
| команда | `/devflow:learn-pr` | уроки из замечаний ревью к своим PR: журнал находок, кандидаты в правила, повторы |
| команда | `/devflow:setup` | установка на машину и подключение проекта |
| команда | `/devflow:rule` | добавить правило в плагин с новой версией |
| хуки | `hooks/hooks.json` | гейт пуша, гейт базы знаний, запрет коммита локальных файлов, миграции только командой, последовательные тесты, запись в GitHub (`gh`) и YouTrack (MCP) по подтверждению, PR только с показанным заголовком и описанием, симлинки worktree, общие правила на старте сессии, циклы агентов по режимам на Stop (`cycles.md`), гейт критики дизайна, PHP-правила по полю `hooks` конфига |
| правила | `rules/general.md` | общие правила поведения, подаются в контекст каждой сессии |

Ревью устроено линзами: один и тот же дифф проходит несколько независимых агентов, каждый с одним вопросом и чистым контекстом. `quality-reviewer` — общий чек-лист дефектов и правила проекта, `security-reviewer` — владение, ввод, секреты, платежи, `db-reviewer` — план запроса на реальной схеме, `black-box-tester` — сценарии спеки без доступа к коду. Линзы запускаются одним ходом на одном SHA, каждая по своему признаку в диффе (`finish.md`).

База знаний и циклы. Карты модулей живут в `architecture_dir` проекта (секция «База знаний» `workflow.md`): `system-mapper` строит их до задачи (area) и обновляет после (feature, troubleshooting), гейт `knowledge-base-check.py` в `pre-push-check.py` не засчитывает дерево без карты по каждому файлу ветки и строки `сверено`. Обязательные агенты по режимам перечислены в `skills/task-workflow/references/cycles.md`; Stop-хук `cycle-check.py` читает транскрипт сессии и один раз блокирует ход, в котором признак режима есть, а агента не было.

Внешние системы. YouTrack — встроенный MCP-сервер инстанса (чтение и, по прямой просьбе и подтверждению хука, запись) плюс клиент `skills/tracker/youtrack.mjs` для скачивания вложений. GitHub — `gh`: PR, ревью, ответы в треды; запись в API GitHub в обход `gh` хук отклоняет.

Модели агентов: исполнители по готовому брифу (`implementer`, `black-box-tester`, `db-reviewer`) на `sonnet`, судьи наследуют модель сессии.

Скиллы срабатывают на фразы («новая задача T-5», «отправь задачу», «что по статусу T-7», «что в работе по бэку»); команды зовутся с префиксом.

- Установка и обновление — `INSTALL.md`.
- История версий — `CHANGELOG.md`; выпуск — `tools/release.sh`, линт пакета — `tools/check.sh`.
- Стандарт скиллов — `docs/skill-standard.md`, линт — `tools/skill-lint.py` (п. 8 `check.sh`).
- План форка — `docs/plan.md`.
