# team-report — отчёт для команды

Применяется ко всему, что уйдёт людям: комментарий в тикет, итог исследования, оценка для тимлида, ответ «что нужно, чтобы…». Чат с пользователем — ревью этого текста, наружу отдаёт он.

Эталон — комментарий тимлида в T-2246 (2026-11-03): 45 строк, читается за минуту, по нему приняли решение. Наш коммент в том же тикете: 1360 слов, шесть абзацев находок до цифр, три списка задач с «5 / 2», абзац допущений — пользователь переписал его сам.

## Скелет

1. **Первая строка — что это, для кого, статус.** «Рабочая оценка для обсуждения внутри команды, не смета клиенту», «Итог исследования, код не менялся». Без неё читатель не знает, можно ли опираться на цифры.
2. **Разделы — этапы работы или пункты приёмки тикета**, нумерованные; в заголовке — итог раздела: `1. Критичный минимум для переключения — 28 ч разработки + 16 ч QA = 44 ч`. Этапы — те, что назвал тикет или тимлид (срочный минимум, полный переход, партнёр); своих категорий объёма («отдельный проект») не выдумывать.
3. **Внутри этапа — блоки по смыслу, не по номерам задач.** Блок — что меняется для бизнеса, одной строкой: «Уведомления провайдера: обработка ошибок, защита от повторного создания способов оплаты». 4–7 блоков на этап; номера задач — хвостом строки как ссылка (`— YK-6`), не заголовком. Часы — таблицей `Блок | Разработка` с итоговой строкой либо `N ч` словами; «5 / 2» без подписей запрещено.
4. **QA — отдельным коротким списком по тому, что проверяется**, не по задачам: «6 ч — аренда, долги, депозиты и возвраты по картам и СБП».
5. **Следующие этапы — два-три предложения**: что входит, принцип отсечения, когда уточняем состав. Полный перечень задач — в файле отчёта, не в комменте.
6. **«Что нужно уточнить» — до пяти пунктов**, только то, что меняет состав работ или часы. Вопрос, на который отвечает код или тикет, не задавать: в T-2246 бизнесу ушёл вопрос про холд по СБП, хотя депозит по СБП уже реализован списанием с возвратом.
7. **Закрывающая строка — диапазон, ориентир, условие**: «Рабочий диапазон 38–56 ч, ориентир 44; после прогона реальных приложений уточняем остаток».

Чего в тексте нет: абзацев находок перед цифрами (находка — строка в том блоке, которому она даёт работу); имён классов, таблиц, статусов (§1 общих правил); «допущений и непроверенного» абзацем — это либо условие в закрывающей строке, либо пункт «уточнить».

## Объём

Комментарий в тикет — один экран: до 40 строк, до 400 слов. Подробности (задачи по шаблону, сравнение сценариев, план с откатом) — файлом `report.md` в каталоге тикета, в комменте ссылка. Не влезает — режь до скелета, не ужимай абзацы.

## Числа

- Часы живут в одном месте — в таблице задач `report.md`. Коммент, план, ответ в чате берут суммы оттуда; второй копии чисел не бывает.
- Суммы считать скриптом по таблице, не в голове: в T-2246 две арифметические ошибки подряд (21–27 вместо 24–30, QA 27 вместо 31) ушли в коммент.
- Срез в чат («кратко по критичным») — та же группировка и те же номера, что в комменте. Другая группировка для пользователя выглядит как другие задачи.
- Перед выдачей — `grep` каждого итога по каталогу тикета: одно значение во всех местах.

## Процесс

- Один отчёт на тикет: `report.md` плюс `reports/tracker-comment.md`. README, plan, tasks и документ по партнёру параллельно не заводить — в T-2246 четыре документа разошлись за час.
- Файл, который пользователь уже открывал, не переименовывать и не уносить в drafts молча: «а где мд файл с задачами?».
- В чат — коммент целиком, не пересказ и не ссылка на файл. «Отправить в тикет» не предлагать.
