# research — исследовательский тикет

Триггеры: «исследуй», «ресёрч», «что нужно, чтобы…», «сравни что есть / чего не хватает», «подготовь оценку и план перехода». Выход — `report.md` и комментарий в тикет, не ветка и не код.

1. **Тикет — до ресёрча, целиком** (скилл `tracker`: MCP YouTrack `get_issue`, `get_issue_comments`, вложения — `youtrack.mjs attachments`). Его критерии приёмки — разделы отчёта, его структура — шаблон задач. В T-2246 ресёрч ушёл раньше чтения тикета, и отчёт пришлось перекраивать под критерии.
2. **Каталог тикета:** `spec.md` (критерии приёмки → будущие разделы), `research/notes/NN-<тема>.md` — заметки субагентов с `file:line`, `report.md` — единственный отчёт, `reports/tracker-comment.md` — коммент по `team-report.md`.
3. **Ресёрч по коду — субагентами по слоям**, по файлу заметок на каждого; заметки для тебя, не для команды, в отчёт не копируются.
4. **Факты о проде** (работало ли, когда переключали, сколько клиентов) не выводить из номеров тикетов, коммитов и названий веток. Такое — «предположение» и вопрос пользователю до попадания в отчёт: в T-2246 ресёрч счёл по тикетам с багами, что ЮKassa работала в проде; она не работала никогда, и это меняло оценку рисков целиком.
5. **`report.md`:** первая строка — срез кода (sha, дата), «код не менялся»; разделы — по критериям приёмки в их порядке. Задачи декомпозиции — по шаблону тикетов команды (заголовки из описания исходного тикета: что сделать и зачем / что посмотреть и посчитать / где именно / критерии приёмки), у каждой dev и QA; сводная таблица часов — единственный источник чисел.
5а. **Критик на выводы.** Каждый вывод `report.md`, из которого следует решение или оценка («переход на X возможен без миграции, потому что…», «провайдер Y не подходит, потому что…»), до п. 7 проходит `devflow:decision-critic` (`brief.md`: утверждение, автор, что проверено; `reports/critic-N.md`). `BLOCK`/`REVISE` — вывод переписывается или уходит в «предположения» до отправки; несущую находку сверь по коду сам.
6. **Оценка** — по секции «Оценка» `workflow.md`, на разработчика с AI, без буфера на ревью. Отдельно: минимальный объём для запуска и что из него сознательно убрано, с риском.
7. **Коммент** — по `team-report.md`, в чат целиком. Цикл режима — `cycles.md`. Разбивка тимлида в ответном комменте — сопоставление с задачами строкой в `reports/notes.md`; отчёт переписывать только по команде пользователя.
