# Resolve PR Comments — замечания ревьюера в своём PR

## Зачем

«Всё решено» без счёта: из семи тредов разобраны пять. Та же ошибка в соседних файлах уехала в прод. «Не согласен» без контрпримера — раунд потерян. Правка по замечанию без ревью несёт то, что ветка уже прошла на finish.

## Когда / когда нет

Когда: URL своего PR с замечаниями; тикет с PR на ревью (`fixes.md` отправляет сюда). Не для: чужого PR (`review-pr`); замечаний тестировщика и CI (`task-workflow` fixes).

## 0. Конфиг проекта

`.claude/workflow.md` основного репозитория (родитель `git rev-parse --path-format=absolute --git-common-dir`): «Git» → `github_repo` (URL PR перебивает), `base`; «Проверки» → `pre_push`, `tests_targeted`, `tests_full`; «Ревью» → карта правил (сами правила — `CLAUDE.md` `[ревьюер]`); «Ответы в PR» → тон. Нет файла — репозиторий из URL, проверки из `.claude/branch-ops.md` или `CLAUDE.md`, тон по репликам в PR; `pre-push-check.py` без `pre_push` не вызывать.

## 1. Протокол

- Первой строкой счёт `Открытых тредов: N (из M резолвабельных)`; сколько открыто — столько закрыто или названо почему нет. `[слово]`
- Ревьюер может ошибаться: разбор по коду до правки; правки после «да» (auto: очевидные без вопроса). `[слово]`
- Шире треда: по всему диффу ветки; новый исход метода — вызывающие до входных точек. `[ревьюер]`
- Входы ревьюера — тестом с его числами, красным до правки. `[слово]`
- Утверждения в ответе и описании PR сверены с кодом, тестом или замером. `[слово]`
- Тексты ответов пользователю целиком; отправка (`gh api …/replies`) — после «ок», подтверждает хук. `[хук]`
- Коммит поверх, без amend и force; `pre-push-check.py` последним; резолв — по слову пользователя. `[хук]`

## 2. Этапы

Шаги дословно — `references/steps.md`; уроки — `references/learn.md`.

| Этап | Вход → выход |
|---|---|
| 1. Обсуждения | URL/ключ → треды `reviewThreads` (GraphQL), все страницы |
| 2. Счёт и разбор | треды → открытые / закрытые / не в счёт |
| 3. Критический разбор | открытые → верен / неоднозначен / спорный; список пользователю |
| 4. Правки | подтверждённое → правка + те же места по ветке, `tests_targeted` |
| 5. Ревью и проверки | коммит → `quality-reviewer` subtask по SHA → `tests_full` при общих модулях, `pre-push-check.py` последним |
| 6. Ответы | тексты → «ок» → ответы в треды |
| 7. Уроки | подтверждённые треды → журнал, кандидаты в правила |

## 3. Цикл

`task-workflow/references/cycles.md`, режим resolve-pr-comments: `decision-critic` до ответа «не согласен» («замечание неверно, потому что …», `reports/critic-N.md`) `[слово]`; `BLOCK` — тред в правку. `quality-reviewer` subtask по коммиту правок до ответов в треды (шаг 5; хук ждёт его по `fix-N.md` типа `ревью`) `[хук]`. Implementer нет — плана нет.

## 4. Отчёт

Полный формат — `references/steps.md`. Скелет:

```
Открытых тредов было: N · ранее (K) · сейчас (M) · спорные (L)
Тесты: <команда> — N passed · Ревью правок: K находок, закрыто M · Проверки: pre_push на <sha> · Ответы: N, отправлены|ждут «ок» · Уроки: N кандидатов
```

## Остановка

Три PR подряд без спорных тредов — разбор формальный, перечитать шаг 3. Критик трижды `CONTINUE` — бриф.

## Самопроверка

- [ ] Счёт по всем страницам `reviewThreads`; замечания проверены по всему диффу (честность).
- [ ] Несогласие прошло критика; правки — ревьюера (честность).
- [ ] Тексты ответов показаны целиком, утверждения подтверждены (честность).
- [ ] `pre-push-check.py` на финальном дереве; ответы — после «ок» (машинно: хуки).
- [ ] Строка журнала по каждой находке (честность).
