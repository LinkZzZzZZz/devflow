# Branch ops — ветки, которые видят другие люди и CI

## Зачем

Force-push без записанного SHA — прежнюю голову не найти. Ребейз поверх правок пользователя. Merge-коммит, выброшенный cherry-pick. Конфликт взят с одной стороны. Пуш до того, как пользователь увидел итог. Один протокол: изоляция, старые SHA, сверка, проверки, стоп перед пушем.

## Когда / когда нет

Когда: ребейз (A), отправка с PR (D), синхронизация своих PR (E). Не для: правок по ревью (`resolve-pr-comments`); ведения тикета (`task-workflow`); пуша без команды в чате.

## 0. Конфиг проекта

`.claude/workflow.md`: «Git», «Worktree», «Проверки» (`pre_push`), «Не коммитить». Нет — `.claude/branch-ops.md`; нет обоих — черновик по `${CLAUDE_PLUGIN_ROOT}/skills/task-workflow/references/workflow-template.md` из `git branch -r`, `.github/workflows/*.yml`, `Makefile`/`package.json`/`composer.json`, `CLAUDE.md`; показать, записать после «ок»; эпик не угадывать. Проверки — `${CLAUDE_PLUGIN_ROOT}/hooks/pre-push-check.py`. `CLAUDE.md` и память пользователя приоритетнее.

## 1. Протокол

Дословно — `references/protocol.md`.
- `git fetch origin --prune`; старые SHA записаны до правок, в отчёт. `[слово]`
- Локальная ветка впереди `origin` — стоп; работа в worktree. `[слово]`
- Merge-коммит в диапазоне — стоп; конфликты — `references/conflicts.md`. `[слово]`
- Сообщения коммитов не трогать. `[attribution]`
- `scripts/verify_moved.py`; проверки на финальном HEAD. `[хук]`
- Стоп перед пушем до команды; в D подтверждают хуки `guard-git-push` (пуш) и `guard-bash-rules` (`gh pr create`). `[хук]`
- После пуша снести worktree; локальную ветку двигать только без своих коммитов. `[слово]`

## 2. Режимы

Определи операцию, читай только её справочник.

| Запрос | Операция | Справочник |
|---|---|---|
| «ребейзни X от master», «подтяни эпик» | A. Ребейз | `references/rebase.md` |
| «засквошь и запушь», «коммит от текущего времени и пушь», «отправь задачу», `/ship` | D. Отправка ветки | `references/ship.md` |
| «в PR конфликты», «снова конфликты в T-21», «проверь мои PR», `/sync-prs` | E. Синхронизация PR | `references/sync-prs.md` |

Вход — ветки и SHA из `origin`; выход — новый SHA локально, отчёт §4.

## 3. Цикл

Агентов нет: проверяют хук `guard-git-push` и `verify_moved.py`. Правки по ревью в D не делать.

## 4. Отчёт

Полный формат — `references/protocol.md`, «Отчёт». Скелет:

```
<Операция>: <ветка> — готово локально, не запушено.
- Было: <SHA> → стало: <SHA> · Перенесено: N · Конфликты: нет|<файл — как>
- Сверка: <verify_moved.py> · Проверки на <SHA>: <команда — результат>
Пуш: <точная команда>. Жду команды.
```

## Остановка

«Пушь» не читая — отчёт длиннее нужного. `verify_moved.py` без расхождений месяц — не убирать: страховка.

## Самопроверка

- [ ] Старые SHA записаны до правок; работа в worktree; `git log --merges` (честность).
- [ ] `verify_moved.py` прогнан (машинно).
- [ ] Дерево засчитано на финальном SHA (машинно: `guard-git-push`).
- [ ] Пуш и PR — после команды и «да» (машинно).
