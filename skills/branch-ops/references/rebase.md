# branch-ops — операция A

Общий протокол (fetch, старые SHA, worktree, конфликты, сверка, проверки, стоп перед пушем) — в `references/protocol.md`, он действует и здесь.

## A. Ребейз ветки на базовую

«Ребейзни public-api-release от master», «подтяни T-123 к эпику».

1. База — из просьбы, иначе из конфига (`branches`: у эпика/релизной ветки указана база). Не ясно — спроси.
2. Worktree от `origin/<ветка>`, `git rebase origin/<база>`.
3. Сверка: `scripts/verify_moved.py origin/<база-старая-точка> <старый SHA ветки> origin/<база> HEAD`, где старая точка — `git merge-base <старый SHA> origin/<база>` до ребейза. Дополнительно, если конфликтов не было: `git diff <старый SHA> HEAD` должен совпасть с `git diff <старая точка> origin/<база>` — ветка поменялась ровно на то, что пришло из базы. Скрипт делает это сравнение сам.
4. **Зависимые ветки.** Если переписываемая ветка — база для других (эпик, релизная), все ветки, отведённые от любого её переписанного коммита, содержат самый ранний из них:
   ```bash
   first=$(git rev-list --reverse <старая точка>..<старый SHA> | head -1)
   git branch -r --contains "$first"
   ```
   Исключи саму ветку. После force-push PR остальных покажут чужие коммиты — перечисли их в отчёте с командой `git rebase --onto origin/<ветка> <старый SHA> <зависимая>` (если зависимая отведена от более ранней точки, вместо `<старый SHA>` — её `git merge-base` со старым SHA). Сам не переноси, если не просили.
5. Пуш по команде: `git push --force-with-lease=<ветка>:<старый SHA> origin HEAD:<ветка>`. Явный SHA в lease важен: без него lease сверяется с `origin/<ветка>`, который мог обновиться фоновым fetch, и защита не сработает.
