# tracker — запросы и чтение данных

## Источники

| Что | Чем | Примечание |
|---|---|---|
| Карточка | MCP `get_issue` (id = ключ `T-12`) | поля, описание, теги, связи, последние комментарии, список вложений |
| Все комментарии | MCP `get_issue_comments` | постранично до конца; у `get_issue` только последние |
| Поля проекта | MCP `get_issue_fields_schema` (проект из `project` конфига) | точные имена полей и допустимые значения: статусы, сторона |
| Поиск | MCP `search_issues` с запросом YouTrack | синтаксис `поле: значение`, ниже |
| Файлы вложений | `youtrack.mjs attachments --key <KEY> --out <каталог>` | REST `GET {YOUTRACK_URL}/api/issues/{id}/attachments`, файл по полю `url` с подписью; вложения комментариев тоже (`comment` в выводе) |
| Пользователь | MCP `find_user` (`me` — текущий), `get_current_user` | логин и имя |

Клиент запускать Node 18+: `node "$DEVFLOW_ROOT/skills/tracker/youtrack.mjs" <cmd>`.

## Модель задач

- **Общая задача** — смысл фичи целиком: зачем, что видит пользователь, критерии приёмки фичи. Поле стороны пустое (в YouTrack показывается «общая»).
- **Подзадачи сторон** — под общей задачей связью «subtask of», у каждой сторона `back` или `front` и своё описание: что делает эта сторона, контракт между сторонами. Значения «обе стороны» нет: фича на обе стороны — это общая задача и две подзадачи.
- Задача одной стороны без фичи (баг экрана, рефакторинг) — сторона заполнена, родителя может не быть.
- Работа и ветка ведутся по подзадаче стороны; общая задача — контекст, её читают вместе с подзадачей.

## Запросы

Синтаксис — Search Query Reference YouTrack Cloud: «Attribute-based search uses the syntax `attribute: value`», для кастомного поля атрибут — имя поля; имя с пробелами — в фигурных скобках (`Stage: {В работе}`); нерешённые — ключевое слово `#Unresolved`.

- Всё нерешённое проекта: `project: T #Unresolved`.
- По стороне: `project: T #Unresolved Сторона: back`. Общая задача каждой строки — связь «subtask of» в `links` ответа `get_issue`.
- Подзадачи общей задачи: `subtask of: T-10`.
- Общие задачи (без стороны): `project: T #Unresolved has: -Сторона` — синтаксис отрицания `has` на живых задачах не сверен; первый ответ сверить с доской, расхождение — сказать пользователю.
- По статусу: `<status_field>: {<значение>}` — поле из `status_field` конфига, значения из схемы.
- По исполнителю: `… for: me` или `… Assignee: <логин>`.
- Поле стороны называется иначе — имя из `side_field` конфига; значения — из `get_issue_fields_schema`.

## «Зависло»

Нерешённая задача в рабочем статусе (не первый по порядку статус вроде «Бэклог» — точные имена из схемы) без обновления 5 дней и больше. Дату обновления брать из ответа `search_issues`/`get_issue`; нет её в ответе — `get_issue` по каждой задаче выборки. Порог 5 дней — по умолчанию, пользователь может назвать свой.

## Чтение тикета для task-workflow

1. `get_issue <KEY>` → summary, описание, статус, исполнитель, сторона, связи.
   - подзадача стороны (есть «subtask of») — прочитать и общую задачу: смысл фичи и критерии приёмки живут там;
   - общая задача (сторона пустая) — `search_issues`: `subtask of: <KEY>`, прочитать подзадачи обеих сторон.
2. `get_issue_comments <KEY>` все страницы → уточнения постановки; зачёркнутое — закрыто.
3. `youtrack.mjs attachments --key <KEY> --out <каталог тикета>/attachments` → открыть картинки и тексты (Read); `error` — назвать.
4. Связанный тикет («см. T-5», связь в `links`) — прочитать тем же способом.

Описание приходит в Markdown YouTrack — пересказываешь ты.
