# retro — уроки сессии и сверка правил с механикой

## Зачем

Пользователь объясняет причину правки на лету («не надо, ломается X»), а через неделю ошибка повторяется: сигнал не стал правилом. Обратный провал — метка `[линтер]` на правиле, которое линтер не ловит (так было с `strict_types` и deptrac): ложная защита. Третий — «ок» на решение пользователя без аргумента, пока его не посчитали.

## Когда / когда нет

Когда: после `finish` и `fixes` тикета, по «/devflow:retro [id | N | пусто]», при подозрении, что правило не сработало. Не для: замечаний ревьюера к PR (`resolve-pr-comments` шаг 7, `/devflow:learn-pr`); правок кода; записи без «ок» на конкретного кандидата.

## 0. Конфиг проекта

Машинные поля `workflow.md` (`pre_push`, `local_wip`, `migrations_dirs`, `serial_only`, `test_process`, `hooks`) и `hooks.json` плагина — на дренаже. Память проекта — `~/.claude/projects/<путь основного репозитория>/memory/`; журнал находок — рядом с `.env` плагина (`lib_env.py env-path`).

## 1. Протокол

- Гейт на запись — пользователь: ничего не записывать до подтверждения конкретного кандидата. `[слово]`
- Транскрипт выбирать явно, печатать имя и размер: соседние сессии пишутся одновременно, промах даёт ретро чужой работы. `[слово]`
- Транскрипт целиком не читать — выборки python/jq; сообщения «на лету» (`absorbed_mid_turn`) обязательны. `[слово]`
- Из worktree `CLAUDE.md` и `.claude/` основного репозитория не правятся — текст пользователю; память и репозиторий плагина писать можно. `[хук]`
- Правило — только со сценарием рождения и прогоном на нём; без прогона — гипотеза в память. `[слово]`
- Ноль кандидатов — нормальный исход. `[слово]`

## 2. Этапы

| Этап | Вход → выход | Справочник |
|---|---|---|
| 1–2. Транскрипт и сигнал | аргумент → файл сессии, реплики пользователя с признаком урока | `references/transcript.md` |
| 3. Кандидаты | сигнал + память + `CLAUDE.md` + журнал → список кандидатов с уровнем | `references/candidates.md` |
| 4–4а. Дренаж и метрики | метки правил ↔ `hooks.json`/`pre_push`; бюджет; метрики сессии и калибровка критика | `references/drain.md` |
| 5. Запись | подтверждённое → память / `CLAUDE.md` / плагин через `/devflow:rule` | `references/record.md` |

Этап 4 выполняется всегда, даже при нуле кандидатов.

## 3. Цикл

Агентов нет. Скилл считает, где цикл (`task-workflow/references/cycles.md`) требовал `decision-critic`, а вызова не было (этап 4а).

## 4. Отчёт

```
Ретро <файл сессии> (<размер>): кандидатов N (записано K, отклонено R) · расхождений меток M · согласий без аргумента A · утверждений без критика B · impl.blind-edit за неделю C · вердикты критика: CONTINUE x / REVISE y / BLOCK z
```

## Остановка

Десять ретро подряд без кандидатов и расхождений меток — порог завышен или правила уже в механике: пересмотреть признаки урока. «Согласий без аргумента» ноль при живых решениях пользователя — греп не ловит форму согласия, поправить выборку.

## Самопроверка

- [ ] Имя и размер транскрипта напечатаны, `mtime` — секунды (честность).
- [ ] Выборка включила `absorbed_mid_turn` (машинно: скрипт этапа 2).
- [ ] Кандидат — со сценарием и результатом прогона (честность).
- [ ] Метки сверены с `hooks.json` и `pre_push` (машинно: этап 4).
- [ ] Записано только подтверждённое; `CLAUDE.md` из worktree не тронут (машинно: хук).
- [ ] Метрики этапа 4а — в сводке.
