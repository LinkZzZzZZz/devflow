# retro — найти транскрипт и извлечь сигнал

## Шаг 1. Найти транскрипт

Каталог транскриптов соответствует рабочему каталогу сессии: `~/.claude/projects/<путь-через-дефисы>/`. **Не делай `cd` перед вычислением пути** — иначе попадёшь в каталог другого проекта. У воркtree свой каталог, и в нём обычно ровно один файл, текущей сессии.

```bash
D=~/.claude/projects/$(pwd | sed 's|[/._]|-|g')
[ -d "$D" ] || { echo "каталог транскриптов не найден: $D"; exit 1; }
N=$(ls "$D"/*.jsonl 2>/dev/null | wc -l | tr -d ' ')
F=$(ls -t "$D"/*.jsonl 2>/dev/null | head -1)
[ -n "$F" ] || { echo "транскриптов нет в $D"; exit 1; }
echo "файлов: $N | выбран: $(basename "$F") | размер: $(du -h "$F" | cut -f1) | изменён $(( $(date +%s) - $(stat -f %m "$F") )) сек назад"
```

**Санитизация пути — заменяются слэши, точки и подчёркивания** (`sed 's|[/._]|-|g'`): проект `app_symfony` лежит в `-…-app-symfony`. Каталог воркtree `/…/api/.claude/worktrees/имя` даёт `-Users-…-api--claude-worktrees-имя` с двойным дефисом: точка перед `claude` тоже становится дефисом. Замена одних слэшей даёт несуществующий путь.

**Проверяй, что переменная не пуста, до любого использования.** Пустой `F` в `du -h "$F"` разворачивается в обход всего каталога и выдаёт километр мусора вместо ошибки.

Переменной с id текущей сессии не существует (`CLAUDE_SESSION_ID` нет; `CLAUDE_CODE_HOST_SESSION_ID` — другой идентификатор, к транскрипту отношения не имеет). Поэтому:

- **файл ровно один** — это он, бери без вопросов;
- **файлов несколько** (основной репозиторий, где сессии копятся) — бери самый свежий, но сверься: его `mtime` должен отличаться от текущего момента на секунды, ведь он пишется прямо сейчас. Если самый свежий изменялся минуты назад, ты смотришь на чужую живую сессию.

**Всегда печатай, какой файл выбран, и его размер.** Молча выбирать нельзя: в основном репозитории соседние сессии пишутся одновременно, и промах тихо даст ретроспективу чужой работы. Пользователь должен иметь возможность возразить.

Если аргумент — число N, возьми `head -N`. Если id — файл `$D/<id>.jsonl`.


## Шаг 2. Извлечь сигнал

Не читай транскрипт целиком: в нём мегабайты вывода инструментов. Вытащи только сообщения пользователя.

```bash
python3 - "$F" <<'PY'
import json,sys,re
SKIP=("<task-notification>","Another Claude session sent a message:","<teammate-message","<command-name>","Caveat:","[Request interrupted")
seen=set()
def emit(ts,txt,tag=""):
    t=re.sub(r"<system-reminder>.*?</system-reminder>","",txt,flags=re.S).strip()
    if not t or t.startswith(SKIP): return
    k=t[:200]
    if k in seen: return
    seen.add(k)
    print(f"--- [{(ts or '?')[11:16]}]{tag}\n{t[:1500]}\n")
for line in open(sys.argv[1],errors="replace"):
    try: d=json.loads(line)
    except: continue
    ts=d.get("timestamp")
    if d.get("type")=="user" and not d.get("isMeta"):
        c=(d.get("message") or {}).get("content")
        t=c if isinstance(c,str) else "\n".join(
            b.get("text","") for b in c if isinstance(b,dict) and b.get("type")=="text") if isinstance(c,list) else ""
        emit(ts,t or "")
    elif d.get("type")=="queue-operation" and d.get("reason")=="absorbed_mid_turn":
        a=d.get("attachment") or {}
        emit(ts, a.get("prompt") or d.get("content") or "", "  [НА ЛЕТУ]")
PY
```

**Сообщения «на лету» обязательны — без них ретроспектива бессмысленна.** Отправленные посреди хода записываются с типом `queue-operation` и `reason=absorbed_mid_turn`, а текст лежит в `attachment.prompt` или `content`, не в `message.content`. Фильтр по одному `type=="user"` их не видит.

Именно они и есть главный материал: пользователь пишет на лету, когда его что-то задело прямо сейчас. В сессии, на которой команда проверялась, оба ключевых замечания — про ручные миграции и про обязательный `declare(strict_types=1)` — пришли так, и наивный фильтр потерял оба.

Записи дублируются (одно сообщение попадает в журнал несколько раз) — дедуплицируй по первым 200 символам текста, как в коде выше. Пометка `[НА ЛЕТУ]` в выводе помогает: такие сообщения стоит взвешивать выше обычных.

Из полученного отбирай только сообщения с признаком урока:

- **пользователь объяснил причину** — «потому что», «тк», «иначе», «ломается», «теряется», «приведёт к»;
- **откат решения** — «не надо», «убирай», «верни как было», «не нравится», «неправильно»;
- **повтор** — одно и то же исправление во второй раз за сессию;
- **эскалация** — CAPS, мат. Поздний сигнал: к этому моменту дефект обычно уже уехал далеко.

Остальное игнорируй. Обычная постановка задачи, уточняющий вопрос и разовая правка вкуса уроками не являются.
