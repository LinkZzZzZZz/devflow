# Review PR — находки списком, на GitHub только выбранное

## Зачем

Ревью по диффу подряд видит код, а не требования: в T-2121 пять ревью пропустили треть недостающих тестов, их нашёл человек вопросом «а где сценарий X?». Второй провал — предположение, опубликованное в тред без проверки по коду. Третий — утверждение автора в описании PR принято на веру. Скилл ведёт ревью по маршруту требований, подтверждает находки кодом, публикует только выбранное одной пачкой.

## Когда / когда нет

Когда: ссылка на чужой PR или тикет на ревью; «автор внёс правки». Не для: своего PR с замечаниями (`resolve-pr-comments`); правок кода в чужой ветке.

## 0. Конфиг проекта

`.claude/workflow.md`: «Тикет» → `key`; «Git» → `github_repo`, `base`; «Ревью» → карта файлов правил; «База знаний» → `architecture_dir`. Правила кода — `CLAUDE.md` `[ревьюер]`. Проектный `.claude/agents/*reviewer*.md` приоритетнее агента плагина.

## 1. Протокол

- Тикет — до кода: ревью проверяет соответствие постановке и отсутствие лишнего. `[слово]`
- Каталог пользователя не переключать: код ветки — `git show origin/<source>:<файл>`. `[слово]`
- Только добавленные и изменённые строки; старый код — «вне PR». `[слово]`
- Находка подтверждена `path:line` новой версии; предположение — вопрос автору. `[слово]`
- На GitHub до ответа ничего не писать; публикация — одно ревью с выбранными комментариями (`gh api …/reviews --input <файл>`) после «публикуй N, M». `[хук]`
- `APPROVE`, `REQUEST_CHANGES` и резолв — только по слову пользователя; по умолчанию `COMMENT`. `[слово]`

## 2. Этапы

| Запрос | Этап | Справочник |
|---|---|---|
| ссылка на PR, тикет на ревью | 1. Контекст → 2. Ревью → 3. Ответ (§4) → 4. Публикация выбранного | `references/review.md` |
| «автор внёс правки, проверь» | 5. Повторная проверка: треды по новому head-коммиту, новый дифф с прошлого ревью | `references/recheck.md` |

Вход этапа 2 — head-коммит PR, диапазон `origin/<base>...origin/<head>`, тикет; выход — `reports/feature-map.md`, отчёт `quality-reviewer`, находки с `path:line`.

## 3. Цикл

По `task-workflow/references/cycles.md`, режим review-pr: `system-mapper` `режим: feature` по диффу PR (маршрут по требованиям) и `quality-reviewer` `режим: pr` — до публикации ревью `[хук]`; `decision-critic` на утверждения автора в описании PR и своё «это не дефект» `[слово]`. Брифы — `task-workflow/references/brief.md`; отчёты — в каталог тикета, без тикета — в scratchpad.

## 4. Отчёт

Нумерованный список, по находке в пункте:

```
N. [крит|важно|мелочь|вопрос|вне PR] path/to/File.php:123 — суть в одну строку
   Коммент: «<готовый текст треда — коротко, на "ты", без канцелярита>»
```

В конце: «Какие публикую? (например: 1, 2, 4; в 3 убери …)». После публикации — «опубликовано ревью: N комментариев» и ссылка. Повторная проверка — список по тредам (исправлено / частично / нет, `path:line`) и новые находки тем же форматом.

## Остановка

Пользователь публикует всё не читая или отклоняет большинство как «мелочь» — калибровка уровней сбита. Маршрут маппера три PR подряд без «Не реализовано» и «Вне сценариев» — маппер для галочки, сверить бриф.

## Самопроверка

- [ ] Тикет прочитан до кода (честность).
- [ ] Маппер и ревьюер вызваны до публикации (машинно: Stop-хук).
- [ ] У находок `path:line`, предположения — «вопрос» (честность).
- [ ] Утверждения автора прошли критика (честность, считает `retro`).
- [ ] Комментариев в файле столько, сколько выбрано; один вызов (машинно: хук показывает число).
